# 芽芽漫步 · YAYA WALK

一款原创、可爱风的微信步行养成原型。用日常步数培育小伙伴，在手绘花园中散步、种花、收集和完成每日小任务。角色和插画均为本项目原创，不使用 Pikmin / Nintendo 的角色、名称或素材。

## 当前可以体验什么

- **花园**：每日步数、成长目标、培育槽、收获新伙伴与浇水互动。
- **漫步**：手绘公园、开始/结束演示散步，以及明确标注的“演示前进”操作。
- **图鉴**：查看原创伙伴与收集进度。
- **我的**：查看本地成长数据和数据模式。
- **本地存档**：重新打开后继续体验；演示和微信运动数据分开结算，不把模拟步数加进真实步数。
- **接入入口**：预留微信运动云函数和用户主动点击的单次定位。

默认使用**演示数据**：初始 3280 步、86 朵花、32 露珠，不需要 AppID、地图 Key、云环境或后台服务。模拟步数、手绘地图和模拟散步不代表真实 GPS 行程；演示操作不会自动统计用户在现实中的行走。

同步微信运动后会进入独立的微信花园，初始花苗进度为零，只结算当天已授权步数；重复或降低的累计步数不会重复用于成长。点击“体验 +500 步”会回到独立的演示花园，不会给微信花园增加模拟奖励。微信模式不提供模拟散步产出。

## 在微信开发者工具中运行

1. 使用近期稳定版微信开发者工具，选择“导入项目”。
2. 项目目录选择此仓库根目录，开发类型选择**小程序**。仓库中的 `project.config.json` 已设置 `miniprogramRoot` 和云函数目录。
3. 初次预览可以使用测试号/游客模式。配置中的 `touristappid` 是占位值，不是可发布的真实小程序 AppID；如工具要求有效 AppID，请创建测试号或使用自己的小程序。
4. 编译后先体验演示模式：增加演示步数、收获苗苗、喂养伙伴、完成任务，再试一次演示散步。

模拟器中可以体验界面和游戏逻辑；运动权限、微信运动开放数据和真实定位需要**自己的 AppID、相应平台配置及微信真机测试**。

## 浏览器预览与检查

需要 Node.js 20 或更新版本。根项目没有第三方运行依赖，无需先安装依赖。

```sh
npm run preview
npm run check
npm test
```

浏览器预览使用同一份游戏引擎，用于快速验证交互和视觉布局。它不提供微信登录、微信运动或微信真机定位能力，也不等于通过微信平台审核。

## 接入真实微信运动

1. 在 `project.config.json` 中替换为自己的小程序 AppID。
2. 为该小程序开通云开发，创建云环境，在 `miniprogram/config.js` 中填写 `cloudEnv`。
3. 在开发者工具中选择对应云环境，右键 `cloudfunctions/syncSteps`，执行“上传并部署：云端安装依赖”。云函数使用固定版本 `wx-server-sdk@4.0.2`。
4. 在小程序管理后台按真实功能配置服务类目、隐私保护指引和运动信息相关声明，完成平台要求的接口开通和审核。
5. 在真机中启用微信运动，从页面上的微信运动入口主动授权并同步。拒绝权限时可继续演示，不会偷偷替换成“真实步数”。

配置示例（环境 ID 不是 AppSecret）：

```js
module.exports = {
  cloudEnv: '你的云开发环境ID',
  demoMode: true,
}
```

同步链路为：用户点击 → 隐私授权 → `wx.login` → `wx.getWeRunData` 获取 `cloudID` → `syncSteps` 云函数 → `cloud.getOpenData`。客户端不会解密开放数据，不存储 `session_key` 或 AppSecret，也不把自报的步数或用户 ID 传给云函数做结算。

云函数检查微信调用者上下文、开放数据 AppID 水印、数据时间和步数格式，返回**北京时间当天**的累计步数。同日重复记录取最大值，重复同步不会累加整份步数；当天数据缺失时会提示重试，不使用昨天的数据或伪造零步代替。

微信运动步数并非连续实时传感器数据；通常在用户主动进入小程序时更新。云函数的读取与格式校验不能保证所有设备数据绝对不可伪造。

## 定位与地图边界

定位仅在用户主动点击相关操作后调用一次 `wx.getLocation({ type: 'gcj02' })`。应用不启动后台定位，不保存或上传精确位置。

页面注册 `wx.onNeedPrivacyAuthorization`，仅在用户主动调用运动或定位接口、平台要求隐私授权时展示自定义说明。用户可以打开微信后台配置的完整隐私指引，通过 `agreePrivacyAuthorization` 按钮明确同意，或拒绝后继续演示。初始化不弹出授权，也不会以自制开关代替平台授权结果。

`app.json` 已声明定位用途及 `requiredPrivateInfos`。上线前还需在微信后台按实际功能填写隐私指引并申请相应接口；用户拒绝定位或设备无法定位时，应继续保留演示体验。

默认的手绘公园是原创演示插画，不是现实底图或附近 POI 数据。定位入口也不代表已实现连续 GPS 轨迹、锁屏种花或地理围栏奖励。若后续加入商业地图、商家 POI 或公共地标，需另行核对地图与数据供应商的授权及微信平台能力。

## 代码结构

```text
miniprogram/
  app.*                 微信小程序入口及全局样式
  config.js             云环境配置，默认空
  pages/index/          四个标签页的界面与交互
  assets/               原创角色和花园 SVG
  services/platform.js  用户触发的运动与定位适配
  shared/game.js        与浏览器预览共用的游戏引擎
cloudfunctions/
  syncSteps/            读取已授权微信运动开放数据
tests/                  游戏引擎与平台适配自动化测试
scripts/                检查与预览工具
```

预览与小程序共用 `miniprogram/shared/game.js` 规则，避免两套演示产生不同行为。

## 验证与发布边界

自动化测试覆盖游戏资源与成长规则，以及平台层的无配置降级、用户主动授权、中国时区跨日、云函数数据格式、重复同步和不可信客户端输入。真实微信运动、真机权限流程、地图服务及微信审核必须在开发者自己的账号中进一步验证。

当前资产保存在客户端本地，尚未实现生产级账户资产账本、云存档、支付、好友后台、限流与完整反作弊。卸载、清理存储或更换设备可能丢失本地存档；不应将其用于有交易或现实兑换价值的奖励。

正式发布前应核实实际游戏类目、主体及备案/出版审批等适用要求，完成隐私、未成年人和数据安全设计。免费、测试号或采用小程序容器不自动免除相关要求。

本项目的本地构建与运行不会自动提交或上传 GitHub，也不会自动上传微信代码或发布小程序。上述发布操作需要单独执行。
